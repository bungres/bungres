# Migration Workflow

Bungres supports both **direct schema pushing** (ideal for rapid prototyping) and **version-controlled SQL migrations** (recommended for staging and production).

---

## 1. Direct Push (`bungres push`)

During early local development, you can apply schema changes instantly without creating `.sql` migration files:

```bash
bun run bungres push
```

Bungres compares your TypeScript schema against the active PostgreSQL database catalog and executes necessary `CREATE TABLE`, `ALTER TABLE`, or `CREATE INDEX` statements directly.

---

## 2. Generating Migrations (`bungres generate`)

When you are ready to version your database changes:

```bash
bun run bungres generate
```

This diffs your TypeScript schema against previous migrations and generates a timestamped `.sql` migration file in your `./bungres` output directory:

```
bungres/
├── 0000_initial_schema.sql
├── 0001_add_user_avatar.sql
└── meta/_journal.json
```

---

## 3. Applying Migrations (`bungres migrate`)

To execute pending `.sql` migration files against target database:

```bash
bun run bungres migrate
```

Bungres maintains an internal tracking table (`__bungres_migrations`) in PostgreSQL to ensure each migration is executed exactly once.

---

## 4. Introspecting Databases (`bungres pull`)

If you have an existing PostgreSQL database and want to generate Bungres TypeScript schema definitions automatically:

```bash
bun run bungres pull
```

This reads the database catalog and outputs type-safe `pgTable()` declarations directly to your schema output path.

---

## 5. Checking Status & Maintenance

### Migration Status (`bungres status`)

Inspect applied vs pending migrations:

```bash
bun run bungres status
```

### Fresh Reset (`bungres fresh`)

Drop all tables and re-execute all migrations from scratch:

```bash
bun run bungres fresh
```

### Refresh Data (`bungres refresh`)

Truncate all tables to quickly reset test data without dropping table structures:

```bash
bun run bungres refresh
```

### Drop Schema (`bungres drop`)

Drop all tables defined in your schema (prompts interactive confirmation, or pass `--force`):

```bash
bun run bungres drop --force
```

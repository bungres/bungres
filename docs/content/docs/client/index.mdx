# Database Client & Connection

The core entrypoint to executing queries in `@bungres/orm` is the `BungresDB` client instance created by the `bungres()` factory function.

---

## Client Initialization

To connect to your PostgreSQL database, pass a PostgreSQL connection string or configuration object to `bungres()`:

```ts
import { bungres } from "@bungres/orm";

// Initialize using connection string
export const db = bungres(process.env.DATABASE_URL!);
```

---

## Native `Bun.SQL` Under the Hood

Bungres is built **exclusively for Bun**. When you call `bungres(connectionString)`, Bungres instantiates Bun's built-in `new Bun.SQL(connectionString)` client directly.

### Advantages of `Bun.SQL`

- **🚀 Ultra-Low Latency**: Directly uses Bun's fast native C++ database bindings without JavaScript driver wrapper overhead.
- **⚡ Native Connection Pooling**: Managed connection pooling built into Bun runtime.
- **📦 Zero External Dependencies**: No need to install `pg`, `pg-pool`, `postgres`, or native build toolchains (`node-gyp`).

---

## Extended Configuration Options

You can pass configuration options directly when initializing `bungres`:

```ts
import { bungres } from "@bungres/orm";

export const db = bungres({
  url: process.env.DATABASE_URL!,
  max: 20,                  // Maximum number of connections in pool (default: 10)
  idleTimeout: 10000,       // Connection idle timeout in ms (default: 10000)
  queryTimeout: 5000,       // Query execution timeout in ms
  logQueries: true,         // Enable SQL query logging (or pass a callback)
  logQueryTiming: true,     // Include execution duration in log outputs
});
```

---

## Connection Pool Monitoring

Track pool capacity and active/idle connection metrics using `db.getPoolStatus()`:

```ts
const status = db.getPoolStatus();
console.log(status);
// { total: 20, active: 2, idle: 18, waiting: 0 }
```

---

## Query Debugging (`getLastQuery`)

Inspect the last executed SQL query, its parameter array, and execution duration:

```ts
const last = db.getLastQuery();
if (last) {
  console.log("SQL:", last.sql);
  console.log("Params:", last.params);
  console.log("Duration (ms):", last.duration);
}
```

## Error Handling & Error Hierarchy

`@bungres/orm` exports a structured error hierarchy for handling database exceptions:

| Error Class | Trigger Scenario | Extra Properties |
| :--- | :--- | :--- |
| `BungresError` | Base class for all ORM errors | Standard `Error` fields |
| `ConnectionError` | Invalid URL, maintenance DB unreachable | `cause` |
| `QueryError` | SQL execution failure or query timeout | `sql`, `params`, `cause` |
| `ValidationError` | Table or schema validation error | Standard `Error` fields |
| `TransactionError` | Transaction failures or rollback errors | `cause` |

```ts
import { QueryError, ConnectionError } from "@bungres/orm";

try {
  await db.select().from(users);
} catch (err) {
  if (err instanceof ConnectionError) {
    console.error("Database connection failure:", err.message);
  } else if (err instanceof QueryError) {
    console.error("Query failed:", err.sql, err.params);
  }
}
```

## Multiple Database Connections

If your architecture uses primary and replica databases (read/write splitting), create separate `BungresDB` instances:

```ts
import { bungres } from "@bungres/orm";

export const dbPrimary = bungres(process.env.PRIMARY_DATABASE_URL!);
export const dbReplica = bungres(process.env.REPLICA_DATABASE_URL!);

// Writes go to Primary
await dbPrimary.insert(users).values({ email: "user@domain.com" });

// Reads go to Replica
const allUsers = await dbReplica.select().from(users);
```

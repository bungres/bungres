# Raw SQL & SQL Commenter

While Bungres provides full type safety through its query builders, you can execute custom parameterized SQL templates or add query comments whenever required.

---

## Parameterized SQL Template Literals (`sql`)

Use the `sql` tagged template literal to construct parameterized SQL fragments. Interpolated JavaScript variables are safely passed as PostgreSQL positional parameters (`$1`, `$2`), preventing SQL injection attacks:

```ts
import { sql } from "@bungres/orm";

const userEmail = "alice@example.com";

// Safe parameterized query chunk
const queryChunk = sql`SELECT * FROM "users" WHERE email = ${userEmail}`;

const rows = await db.execute(queryChunk);
```

### Combining SQL Chunks (`sqlJoin`)

Join dynamic array of SQL expressions safely:

```ts
import { sql, sqlJoin } from "@bungres/orm";

const conditions = [
  sql`status = ${"active"}`,
  sql`age >= ${21}`,
];

const combined = sql`WHERE ${sqlJoin(conditions, sql` AND `)}`;
const rows = await db.execute(sql`SELECT * FROM "users" ${combined}`);
```

## Raw Query Execution (`db.raw`)

To run raw unparameterized SQL strings (e.g. for DDL migration statements or administrative commands):

```ts
const tables = await db.raw(`
  SELECT table_name 
  FROM information_schema.tables 
  WHERE table_schema = 'public'
`);
```

---

## SQL Commenter (`.comment()`)

Add diagnostic comments into generated SQL queries for debugging, query tracing, or APM monitoring (e.g., Datadog, New Relic, pganalyze):

```ts
const activeUsers = await db
  .select()
  .from(users)
  .where(eq(users.active, true))
  .comment("controller:UserController#index action:fetchActiveUsers");
```

This appends a SQL comment to the generated statement sent to PostgreSQL:

```sql
SELECT "id", "email", "username", "full_name", "active" 
FROM "users" 
WHERE "active" = $1 
/* controller:UserController#index action:fetchActiveUsers */;
```
